====================================================
  ForecastExplanation — config.yaml Options Guide
====================================================

The config.yaml file defines one or more named "runs" to execute.
Each top-level key is a run name (e.g. "run_baseline"), and its
value is the configuration for that run. Runs are executed sequentially.

The optional top-level "defaults" block is merged into every run and a run's own options override it .


------------------------------------------------------
TOP-LEVEL STRUCTURE
------------------------------------------------------

  defaults:           # Optional, any run option
    workers: 12

  run_name:           # Arbitrary name for the run
    region: ...
    cities: {...}
    dates: [...]
    output_path: path/to/output
    workers: N
    clustering: true/false
    save_images: true/false
    debug: true/false
    force: <stage>
    stop_after: <stage>
    clean: [grib, cut, extracted]
    fold_rm: {...}


------------------------------------------------------
PIPELINE STAGES
------------------------------------------------------

Stages run in this order; "force" and "stop_after" refer to them:

    data         download + cut GRIBs
    extraction   build feature maps from the cuts (+ clustering)
    features     TOBAC feature detection and tracking
    reasoning    fronts/segments reasoning and ground truth generation
    translation  FOLD-RM dataset generation
    learning     FOLD-RM training

Every stage skips days that are already done, unless forced.


------------------------------------------------------
OPTIONS
------------------------------------------------------

region  (optional, default: FVG)
  The geographic area to process. Can be specified in three ways:

  a) Preset string:
       region: FVG           # Friuli-Venezia Giulia [11,15,44.5,48]
       region: ITALY         # Italy bounding box    [10,16,42,48]

  b) Bounding box (list of 4 floats: [lon_min, lon_max, lat_min, lat_max]):
       region:
         bounds: [-3, 3, 42.7, 45.8]

  c) Bounding box + custom cities + custom radius:
       region:
         bounds: [-3, 3, 42.7, 45.8]
         radius: 5.0
         cities:
           CityName:
             lat: 46.1
             lon: 13.0
       Custom cities override the built-in city list for this run.
       Only cities whose lat/lon fall within the bounds are used.
       The 'radius' parameter (optional, default 20.0) defines the
       search radius in kilometers around each city for calculating
       mean feature values.

------

dates  (required)
  List of dates or date ranges to process (dates format: YYYY-MM-DD).
  Supports single dates as well as date range dictionary objects:

    dates:
      - 2009-01-02                           # Single date
      - start: 2009-01-05                   # Range with start and end (inclusive)
        end: 2009-01-08
        step: 1                              # Optional, days between dates

------

output_path  (optional, default: "runs/<run_name>")
  Folder for all outputs of this run.

------

workers  (optional, default: 12)
  Parallel worker processes.

  CLI: --workers N

------

force  (optional, default: none)
  Recompute the given stage and every stage after it.

    force: learning      retrain FOLD-RM only
    force: translation   + regenerate the dataset
    force: reasoning     + reasoning and ground truth
    force: features      + TOBAC
    force: extraction    + feature maps (tmp_data except CERRA_cut)
    force: data          everything (downloaded GRIBs are still reused)

  CLI: --force <stage>

------

stop_after  (optional, default: learning)
  Last stage to run.

    stop_after: data          only download and cut the GRIBs
    stop_after: translation   build the dataset, skip training

  CLI: --stop-after <stage>

------

clean  (optional, default: [])
  Intermediate data to delete for this run's dates once the run
  completes successfully (nothing is deleted if the run fails):

    grib        downloaded GRIBs in tmp_data/original_CERRA. This
                folder is shared by every run, so other runs will
                have to download those days again.
    cut         region-cut NetCDFs (<output_path>/tmp_data/CERRA_cut)
    extracted   feature maps (<output_path>/tmp_data/extracted_data
                and clustered_data)

  CLI: --clean grib cut ...

------

clustering  (optional, default: false)
  If true, enables clustering during data extraction and runs TOBAC
  on the clustered data instead of the discrete one.

  CLI: --clustering / --no-clustering

------

save_images  (optional, default: false)
  If true, save TOBAC's input/output images and the region legends.

  CLI: --save-images / --no-save-images

------

debug  (optional, default: false)
  If true, sets logging level to DEBUG.

  CLI: -d / --debug / --no-debug

------

fold_rm  (optional)
  FOLD-RM (CUDatILP) training on the translated dataset. One model set
  per label (prev_pioggia, prev_cloud), written to <output_path>/fold_rm/.

    fold_rm:
      strategy: one_vs_rest   # or multiclass, ordinal
      ratio: 0.7              # FOLD-RM exception ratio, (0, 1]
      split: date             # hold out whole days; row = stratified by row
      test_ratio: 0.3         # held-out fraction of days (or rows), (0, 1)
      seed: 42
      min_support: 0          # drop rules holding for fewer training rows
      min_exception_support: 0  # drop exceptions correcting fewer training rows
      gpu: false              # fitGPU, needs the `gpu` extra (cupy)
      output: fold_rm         # models folder inside output_path

  Runs that share an output_path share its data (nothing is extracted
  or downloaded twice) but need a different "output" each, or they
  overwrite each other's models.

  Strategies:
    one_vs_rest  one FOLD-RM model per class ("class_<c>_vs_rest")
    multiclass   a single FOLD-RM model over all the classes
    ordinal      one model per class boundary, "ge_<c>" = the label is at
                 least c (classes ordered by their code).

  metrics.json holds per-model scores under "tasks" and, under "combined",
  the merged prediction over the original classes: accuracy, macro F1,
  balanced accuracy, per-class scores and the confusion matrix.


------------------------------------------------------
NOTES
------------------------------------------------------

- CLI flags override the config file for every run, and can also
  turn options off (e.g. --no-clustering).
- The config file path itself can be changed with --config <path>.
- See config.yaml.example for a full example.
