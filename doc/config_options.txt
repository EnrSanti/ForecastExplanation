====================================================
  ForecastExplanation — config.yaml Options Guide
====================================================

The config.yaml file defines one or more "runs" to execute.
Each top-level key is a run name (e.g. "run_baseline"), and its
value is the configuration for that run.

If the file contains "dates" or "region" at the top level, the
whole file is treated as a single anonymous run.


------------------------------------------------------
TOP-LEVEL STRUCTURE
------------------------------------------------------

  run_name:           # Arbitrary name for the run (used for output folder)
    region: ...
    dates: [...]
    force: N
    clean: N
    clustering: true/false
    debug: true/false
    just_cut: true/false
    save_images: true/false
    skip_learning: true/false
    workers: N
    output_path: path/to/output
    fold_rm: {...}

Multiple run blocks can coexist in the same file and will be
executed sequentially.


------------------------------------------------------
OPTIONS
------------------------------------------------------

region  (required)
  The geographic area to process. Can be specified in three ways:

  a) Preset string:
       region: FVG           # Friuli-Venezia Giulia [11,15,44.5,48]
       region: ITALY         # Italy bounding box    [10,16,42,48]

  b) Bounding box (list of 4 floats: [lon_min, lon_max, lat_min, lat_max]):
       region:
         bounds: [-3, 3, 42.7, 45.8]

  c) Bounding box + custom cities + custom radius:
       region:
         bounds: [-3, 3, 42.7, 45.8]
         radius: 5.0
         cities:
           CityName:
             lat: 46.1
             lon: 13.0
       Custom cities override the built-in city list for this run.
       Only cities whose lat/lon fall within the bounds are used.
       The 'radius' parameter (optional, default 3.0) defines the 
       search radius in kilometers around each city for calculating 
       mean feature values.

------

dates  (required)
  List of dates or date ranges to process (dates format: YYYY-MM-DD).
  Supports single dates as well as date range dictionary objects:

    dates:
      - 2009-01-02                           # Single date
      - start: 2009-01-05                   # Range with start and end (inclusive)
        end: 2009-01-08
        step: 1                              # Optional, days between dates

------

force  (optional, default: 0)
  Controls how aggressively cached/existing results are recomputed.
  Acts as a counter — higher values rerun more stages:

    force: 0   No forced recomputation (use cached results).
    force: 1   Re-run FOLD-RM training.
    force: 2   + translation.
    force: 3   + reasoning and ground truth.
    force: 4   + feature extraction.
    force: 5   + data extraction (everything).

  Equivalent CLI flag: -f (repeat for higher levels, e.g. -fffff = force 5).

------

clean  (optional, default: 0)
  Controls cleanup of temporary folders before running.

    clean: 0   No cleanup.
    clean: 1   Light cleanup of tmp folders.
    clean: 2   Delete all temporary data.

  Equivalent CLI flag: -c / -cc.

------

clustering  (optional, default: false)
  If true, enables clustering during data extraction.
  Clustered data is used as input for feature detection.
  If false, discrete (non-clustered) data is used instead.

  Equivalent CLI flag: --clustering.

------

debug  (optional, default: false)
  If true, sets logging level to DEBUG for all modules, producing
  verbose output useful for troubleshooting.

  Equivalent CLI flag: -d / --debug.

------

just_cut  (optional, default: false)
  If true, only download and cut the GRIB files, then stop.

  Equivalent CLI flag: -jc / --just-cut.

------

save_images  (optional, default: false)
  If true, save visualisation images of the tracking results.

  Equivalent CLI flag: --save-images.

------

skip_learning  (optional, default: false)
  If true, stop after translation without training FOLD-RM.

  Equivalent CLI flag: --skip-learning.

------

workers  (optional, default: 12)
  Parallel worker processes, one day each, used by every per-day
  stage. A failed day is logged and the others continue.

------

output_path  (optional, default: "runs/<run_name>")
  Folder for all outputs of this run.

------

fold_rm  (optional)
  FOLD-RM (CUDatILP) training on the translated dataset. One model set
  per label (prev_pioggia, prev_cloud), written to <output_path>/fold_rm/.

    fold_rm:
      strategy: one_vs_rest   # or multiclass
      ratio: 0.7              # FOLD-RM exception ratio
      test_ratio: 0.3         # held-out fraction (stratified split)
      seed: 42
      gpu: false              # fitGPU, needs the `gpu` extra (cupy)


------------------------------------------------------
NOTES
------------------------------------------------------

- CLI flags always override the corresponding config.yaml option
  when both are provided.
- The config file path itself can be changed with --config <path>.
- See config.yaml.example for a full example.
